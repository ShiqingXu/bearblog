自打前两天在公司电脑上用 antigravity 出发了风控之后，开始看能不能申请公司采购的那些AI 工具。找了一些内部文档，看到 Claude 是面向全部开发者，而公司自研了一个 agent 是面向全员的。

于是先申请了自研工具，走了两个 OA 审批流程才申请下来，一个是那个工具的网站访问权限，一个是登录时需要用到的公司的一个效率平台的权限。花了两天时间审批通过之后，下载试用了。

目前只能作为 IDE 的插件使用，我选择了 vscode 插件。有多种模型可以选择，包括 GPT、Claude 和 Gemini，以及国内的 DeepSeek 等。尝试先用 Claude 写了个小 demo，虽然不太好用，但是能用。

试用过程中发现我电脑上的 Python 环境大有问题，花了很长时间、尝试了很多办法，最终通过微软官方的一个车小工具卸载干净了。重装之后这个插件就怎么都用不了。

于是试探性的去问了一下 Claude Code 的管理员，非研发人员能不能用，结果对方直接给了我一个 API Key。这个故事告诉我们，多问一句没坏处，有时候文档上写的规则并不一定是死的。

我以为拿到 API Key 之后很快就能用上，没想到折腾了两个多小时才最终配置成功。首先是环境变量的问题，由于 Claude Code 不能在中国大陆使用，所以安装启动之后是会报错的。在环境变量里配置了好几条记录，设置了公司的代理，API Key 也在环境变量是设置好，安装了公司的根证书，等等一系列操作下来，始终提示中国地区不能使用。

同时安装了 vscode 插件，插件上始终提示的错误是在 git bash 的环境变量路径里找不到对应的程序。解决这个问题的过程中，发现一个奇怪的现象。

如果我是在 terminal 中启动 Claude，则提示就是中国地区不能使用，尽管我已经配置好了环境变量并设置好了公司代理。

如果是在 git bash 中启动，则提示就是 bash 的环境变量找不到。

最终通过多轮跟网页版 Claude 的聊天，先在 bash 中解决了问题，之后 terminal 中的也解决了。至于具体问题，由于是在公司内网的版本上聊的，我现在也有点儿记不住了，就不详述了。反正这个问题也只会在公司电脑上出现，自己电脑上面对的是完全不痛的问题。

写了几个小 demo 之后，感觉确实不错，后续要逐步融入自己日常工作的流程中。
